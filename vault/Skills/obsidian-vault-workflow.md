# Obsidian Vault Workflow

## מה הסקיל עושה
פרוטוקול ניהול ה-vault כזיכרון ארוך טווח של הפרויקט — קריאה לפני כל משימה, כתיבה בסיום.

## מתי מפעילים
בתחילת **כל** משימה ובסיומה. גם coding, content, ארכיטקטורה, bugfix, review.
היוצא מן הכלל היחיד: שאלות read-only שלא מייצרות שום החלטה.

## שלב 1 — לפני המשימה
1. קביעת נושא המשימה בביטוי קצר
2. חיפוש קובץ נושא תואם ב-vault
3. קריאת הקובץ (Overview + כל Session Log)
4. קריאת 2-3 רשומות אחרונות ב-Meeting Notes

## שלב 2 — אחרי המשימה
1. עדכון (או יצירת) קובץ נושא
2. עדכון Overview אם ההיקף השתנה
3. הוספת רשומת session log חדשה בתחתית
4. עדכון Open Questions
5. קריאה חזרה לאימות

## מבנה קובץ נושא
```
# Topic Title
## Overview
## Open Questions
## Session Log
### YYYY-MM-DD — title [status]
```

## תיקיות הvault
- `Meeting Notes/` — קוד, ארכיטקטורה, החלטות
- `Content Briefs/` — briefs תוכן
- `Publishing Log/` — ריצות פרסום, תוצאות
- `Brand Guidelines/` — קול, ויזואל, טון
- `Skills/` — תיעוד סקילים
