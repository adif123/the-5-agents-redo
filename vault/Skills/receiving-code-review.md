# Receiving Code Review

## מה הסקיל עושה
מגדיר כיצד לטפל בפידבק של code review — בדיקה טכנית לפני יישום, לא הסכמה עיוורת.

## מתי מפעילים
כשמקבלים פידבק על קוד, לפני יישום הערות — בעיקר כשהפידבק נראה לא ברור או שנוי במחלוקת.

## עקרונות מרכזיים
- **וודא לפני שמממש** — בדוק שההצעה נכונה לcodebase הזה
- **אל תסכים בצורה חיובית ("You're absolutely right!")** — פשוט פעל
- **אם לא ברור — שאל לפני שמממש כלשהו** (פריטים עשויים להיות קשורים)
- **פידבק חיצוני = הצעה לבחון, לא פקודה לבצע**

## סדר יישום
1. הבהרת כל הפריטים הלא ברורים
2. blocking issues (שברים, אבטחה)
3. תיקונים פשוטים
4. תיקונים מורכבים
5. בדיקה אחרי כל תיקון בנפרד
