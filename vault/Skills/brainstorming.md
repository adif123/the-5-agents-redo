# Brainstorming

## מה הסקיל עושה
הופך רעיון לעיצוב מלא ומאושר לפני שנוגעים בקוד. דיאלוג שיתופי: שאלות → 2-3 גישות → design doc → אישור משתמש.

## מתי מפעילים
לפני כל עבודה יצירתית — פיצ'ר חדש, קומפוננט, שינוי פונקציונליות. גם פרויקטים "פשוטים" עוברים את התהליך.

## תהליך בקצרה
1. סריקת הפרויקט הקיים
2. שאלות מבהירות (אחת בכל פעם)
3. הצעת 2-3 גישות עם trade-offs
4. הצגת עיצוב בסעיפים — אישור אחרי כל סעיף
5. כתיבת design doc → `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`
6. מעבר ל-writing-plans

## HARD GATE
**לא מממשים כלום לפני שהמשתמש אישר את העיצוב.**
